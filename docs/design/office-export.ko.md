**버튼으로 요청**합니다.

## 1. 지금

- 토론 결과는 Markdown 보고서입니다. 디자인 프로젝트는 승인된 `write_artifact` 액션으로 버전이 있는 산출물(`.md`, `.mmd`, `.svg`)을
  `design-artifacts/`에 저장하고, Artifacts 탭에서 보며 E2/E3로 내보냅니다. 코드·ops 프로젝트는 보고서에서 사람이 "문서로 보관"을 누를 때만
  그런 버전이 생기고(5장 (c)), 그 전에는 보고서가 `decisions/projects/` 아래에만 있습니다.
- DOCX·PPTX를 쓰는 코드는 없습니다. Python 엔진은 표준 라이브러리만 씁니다(`CLAUDE.md`, 고정된 결정).

## 2. 결정

1. **Markdown이 정본입니다.** DOCX·PPTX는 파생 파일이며 고치지도, 다시 읽지도 않습니다.
2. **직접 OOXML(A)을 먼저.** `zipfile`과 고정 XML 템플릿으로 의존성이 없어 허브 릴리스 구조가 바뀌지 않습니다.
   B(`python-docx`, `python-pptx`, `lxml` 필요)는 A로 부족할 때만 정하며, `design-project.md`의 열린 문제(ARM 허브
   릴리스에 의존성을 싣는 방법)도 그때 풀어야 합니다.
3. **버튼이 변환을 시작합니다.** 결과 승인 뒤 엔진이 자동 변환하지 않습니다. Results 탭과 Artifacts 탭의 저장된
   Markdown 버전에 "DOCX 만들기" / "PPTX 만들기" 동작이 붙습니다.

## 3. 버튼이 요구하는 규칙

`AGENT_TOKEN` 뒤의 새 쓰기 엔드포인트이므로 좁게 만듭니다.

- **입력은 저장된, 검증을 통과한 Markdown 버전**(`thread`, `version`, `name`)이며 클라이언트가 보낸 텍스트가 아닙니다.
  `artifact_ops.py`의 검증과 비밀 스캔을 이미 통과한 파일이고, 변환기는 파일을 다시 읽어 매니페스트의 sha256과 맞는지
  확인한 뒤 씁니다.
- **출력은 같은 버전 디렉터리의 새 파일**(`<name>.docx` / `<name>.pptx`)이며 매니페스트에 **원본 파일명과 sha256**을
  함께 적습니다. 버전은 불변입니다. 변환은 새 버전을 만들지 않고 해당 버전 기록에 파일을 더하며, 덮어쓰기는 거부합니다.
- **매크로 없는 형식만.** `.docm` / `.pptm`, VBA 파트, 외부 관계(Markdown 검증이 거부하는 원격 하이퍼링크, 외부 이미지)는
  넣지 않습니다. 문서 안 링크와 `http(s)` 링크는 URL을 보여 주는 텍스트로만 둡니다.
- **다운로드는 항상 `Content-Disposition: attachment`** 와 고정 MIME으로 하고, 대시보드는 인라인으로 렌더하지 않습니다.
  기존 `artifactFile` 규칙(읽을 때마다 sha256 확인, 심볼릭 링크 거부)이 그대로 적용됩니다.
- **감사.** 변환마다 버튼을 누른 주체(API가 이미 기록하는 actor), 원본 sha256, 결과 sha256을 이벤트로 남깁니다.
- **크기 제한.** 산출물 바이트 한도를 넘는 원본과 안전 한도를 넘는 결과는 거부합니다.

### D2: Markdown을 DOCX로 (2026-10-27 구현, 2026-10-28 배포)

- **구성.** `office_ooxml.py`(XML 텍스트 정리, 결정적 zip 작성, `check_package`), `office_docx.py`(`markdown_to_docx`),
  `artifact_ops.py`의 `ArtifactStore.convert`, `guardian.py --artifact-convert NAME --project P --thread T
  --artifact-version artifact@vN [--artifact-format docx]`, 경로 `POST /api/threads/{thread}/artifacts/{version}/convert`
  (본문 `{"name": "<파일>.md"}`, `artifact_handler.go`), 산출물 탭의 "Word 문서로 만들기" 버튼.
- **파생 파일 이름은 `<stem>.docx`**(`overview.md` → `overview.docx`)라서 목록에서 짝이 보입니다. 매니페스트 항목에
  `source`, `source_sha256`, `converted_at`이 붙습니다. 이미 있는 `.docx`는 덮어쓰지 않습니다(종료 코드 4, HTTP 409). CLI
  종료 코드: 2 잘못된 입력·거절, 3 없는 프로젝트·토론·버전·파일(만료된 것 포함), 4 이미 있음. API는 400, 404, 409로 옮깁니다.
- **파생 파일은 원본을 따라갑니다.** 새 버전은 원본 `.md`가 그 버전에서 바뀌지 않은 동안에만 `.docx`를 이어받고, 원본을 다시
  쓰면 낡은 `.docx`는 버립니다(만든 적 없는 텍스트를 설명하는 파생 파일은 없다). 보관 기간이 지나면 `.docx`도 버전과 함께
  지워집니다. `ArtifactStore.read`는 텍스트만 돌려주므로 `.docx`가 토론 에이전트에게 닿을 수 없고, `write_artifact`는 이
  확장자를 여전히 거절합니다.
- **관문.** 원본은 매니페스트 sha256과 같아야 하고 산출물 한도(262144바이트) 안이어야 합니다. 결과는 `check_package`(온전한 zip,
  안전하고 겹치지 않는 이름, VBA·내장 개체 없음, 모든 부분의 콘텐츠 타입, XML 파싱, 대상이 존재하는 내부 관계만)와 2 MiB 상한을
  통과해야 저장됩니다. 파일을 먼저 하드링크로 제자리에 두고(그 사이 같은 이름이 생기면 실패하므로 덮어쓰지 않음) 매니페스트를 원자적으로 다시 쓰며,
  매니페스트 쓰기가 실패하면 파일을 다시 지웁니다. 같은 원본은
  같은 바이트(고정 zip 타임스탬프), 곧 같은 sha256이 됩니다.
- **제공.** `.docx`는 `artifact_handler.go`의 제공 형식에 들어 있지만 `?download=1`과 관계없이 항상
  `Content-Disposition: attachment`, 고정 MIME, `nosniff`, 샌드박스 CSP로 나갑니다. 감사 줄은 `artifact convert
  <이름>@v<n> -> docx`, `source_sha256=... result_sha256=...`, 요청자입니다.
- **표준 라이브러리 방식의 한계:** 이미지는 대체 텍스트로, 링크는 URL을 보여 주는 텍스트로(하이퍼링크 관계 없음), HTML은 텍스트로
  바뀝니다. 표, 목록(아홉 단계까지, 글머리표 문자와 들여쓰기로 표현), 인용, 코드 블록, 작업 목록 표시는 지원합니다.
- **대시보드.** 버튼은 산출물 탭의 Markdown 행에만 있고 결과 탭에는 없습니다. 코드·ops 프로젝트의 토론 보고서는 저장된 버전이
  아니어서 파일을 붙일 버전이 없고, 결과 탭은 설계 산출물을 토론 ID로 묶어 보여 주며 "산출물 보기"로 산출물 탭에 닿습니다. 변환 뒤에는
  목록을 다시 읽습니다. `.docx` 행은 내려받기 전용(텍스트로 읽거나 화면에 보이지 않음)이고, 데스크톱 내보내기가 텍스트만
  쓰므로 내보내기 폴더에서도 빠집니다. **데스크톱 앱은 아직 `.docx`를 내려받지 못합니다**(저장 명령이 텍스트를 쓰고, 웹뷰 안에서는
  Blob 링크 내려받기가 되지 않음). 앱이 그렇게 알리고 브라우저를 안내합니다.
- **확인한 것:** 단위 테스트(적대적 Markdown 코퍼스, 저장소 규칙, CLI 종료 코드), Go 경로 테스트(CLI 인자, 감사 줄, 거절, 자격
  증명, 첨부 전용 제공), 웹 테스트(버튼 규칙, 변환과 갱신, 바이너리 내려받기), `scripts/ci.sh` 전체. 앞서 만든 샘플은
  LibreOffice에서 제대로 보였습니다(한글 글리프 공백은 샌드박스에 글꼴이 없어서입니다). **Microsoft Word에서 파일 열기는 2026-10-28 운영자가
  확인했습니다(`dashboard-ui` 산출물을 변환해 브라우저 대시보드에서 내려받음). 보고된 결함은 없습니다.** D2 완료 조건을 모두 충족했습니다.

### D3: Markdown을 PPTX로 (2026-10-28 구현, `b50af88`로 배포)

- **구성.** `office_pptx.py`(`markdown_to_pptx`), `md_parse.py`(Markdown 블록·인라인 파서, 두 변환기가 문서를 똑같이 읽도록 `office_docx.py`에서
  옮김), `office_ooxml.check_package(data, main_part, max_parts)`(슬라이드 하나가 부분 둘이라 PPTX는 자기 한도를 쓰고 DOCX는 64 유지),
  DOCX에서 일반화한 `ArtifactStore.convert(version, name, target)`(`--artifact-format docx|pptx`, 경로 본문의 `format` 필드). 파생 이름은 `<stem>.pptx`이고
  이름, 매니페스트 항목, 이어받기, 종료 코드, 관문, 첨부 전용 제공에 대한 D2의 규칙이 그대로 적용됩니다. 리팩터링 전후 DOCX 바이트가 같음을
  코퍼스 해시로 확인했습니다.
- **슬라이드 규칙.** 첫 블록이 1단계 제목일 때만 제목 슬라이드를 만들고(그 뒤 첫 짧은 문단, 폭 160 이하가 부제목), 1·2단계 제목마다 슬라이드가 시작되며,
  더 깊은 제목은 슬라이드 안의 굵은 줄로 남습니다. 첫 제목 앞의 글은 제목 없는 슬라이드에 들어갑니다. 빈 제목과 구분선은 슬라이드를 만들지 않고,
  글이 없는 문서는 거절합니다.
- **잘라 내지 않습니다.** 슬라이드 하나는 본문 11줄(넓은 CJK 글자는 폭 2, 코드 줄은 0.75줄)이고, 넘치면 `제목 (2)`, `제목 (3)`
  슬라이드로 이어지며 문단은 공백에서 나뉩니다. 표는 자기 슬라이드에 8행씩 헤더를 반복해 담고, 열이 20개를 넘으면 거절하며 슬라이드가 60장을 넘는 문서도
  거절합니다(메시지에 "slides"가 들어감). 텍스트는 인라인 Markdown을 읽기 전에 나뉘므로 폭에 표시 문자가 포함되고(많아야 슬라이드가 하나 더 생김),
  긴 문단이 강조나 링크 구간 한가운데에서 잘리면 표시 문자가 두 슬라이드에 글자 그대로 보입니다. 알려진 거친 부분이며 데이터 손실은 아닙니다.
- **모양.** 고정된 중립 마스터 하나에 레이아웃 둘(제목, 제목과 본문), 글꼴은 Calibri(동아시아 글자는 맑은 고딕), 코드는 Courier New입니다. 글머리표는 마스터의 것을 쓰고, 번호나 작업 표시처럼 글자로 된 표시는
  글머리표를 꺼서 겹치지 않게 합니다.
- **대시보드.** `MakeOffice`는 Markdown 행마다 아직 없는 형식의 버튼을 하나씩 보여 줍니다("Word 문서로 만들기", "PowerPoint로 만들기"). 파생 파일 분기는 `.docx`와 `.pptx`에
  공통입니다. 데스크톱 앱은 둘 다 아직 내려받지 못합니다.

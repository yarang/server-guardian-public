# 단독 에이전트: 역할 하나, 판정자 없음, 읽기 전용 (설계)

[English](solo-agent.md) | 한국어

상태: 2026-10-30 제안. 같은 날 운영자가 "역할 하나를 단독으로 실행"하는 해석(해석 A)을 골랐다. S1과 S2는 2026-10-30에 구현해
`06531f9`로 배포했다. S3도 같은 날 구현해 `c5d9d45`로 배포했다. 일반(프로젝트 없는) 모드는 2026-10-30에 결정·구현했다(결정 6, 구현 메모 참고). 같은 날 운영자의 말로
provider 범위를 넓혔다(`zai`를 뺀 모두).
출발: "단독 에이전트 실행도 고려해볼 수 있을까?" 토론은 언제나 판정자, jev 게이트, 액션 검증으로 끝난다. 때로는 그
장치 없이 에이전트 하나가 코드(또는 호스트)를 읽고 빠르게 답하기만 바랄 때가 있다.

## 문제

지금 에이전트를 돌리는 방법은 모두 토론이다. 가장 작은 흐름(`draft` 하나, `flow-templates.ko.md` T3a)도 라운드의
공통 마감으로 끝난다. 그 마감 덕분에 결과를 믿고 행동할 수 있지만, 판정자 호출과 게이트와 스레드 비용이 든다.
"재시도 로직이 어디 있고 무슨 일을 하나?" 같은 질문에는 과하다. 그래서 사람들은 채팅창에서 묻고, 거기서는 인용도
검증도 없다.

## 결정 범위와 비목표

- 단독 실행은 **흐름이 아니다**. `team-flows.ko.md`와 `flow-templates.ko.md`는 "판정자 없는 흐름"과 "jev 게이트 없는
  승인"을 비목표로 두며, 이 문서는 그것을 건드리지 않는다. 단독 실행에는 판정자, 라운드, 스레드, 승인이 없고
  결과가 그렇게 표시된다.
- **읽기 전용이고 참고용**이다. 저장소를 읽고(읽기 전용 ops 점검도 가능) 답한다. 실행할 수 있는 것은 아무것도
  제안하지 않는다.
- 새 LLM 접근을 만들지 않는다. 같은 공급자(`claude`, `codex`, `agy`, 키가 있으면 `zai`), 같은 CLI 래퍼, 같은 자격
  증명 규칙(키나 로그인 파일을 호스트 사이에 복사하지 않음).
- Python은 표준 라이브러리만 쓴다. Go 허브는 얇은 경로만 더하고 모델은 돌리지 않는다.

## 모델

```
질문 + 프로젝트 (+ 역할 페르소나, 공급자)  ->  에이전트 세션 하나  ->  답 + 검사 결과
```

- **역할.** 기존 목록(`PersonaManager`)의 페르소나, 기본값은 `expert`. 페르소나 글이 상시 지시이며 팀은 필요 없다.
  판정만 하는 역할(`judge`)은 거부한다.
- **도구.** 토론 에이전트와 같은 읽기 전용 저장소 도구: ```repo 블록 규약, `claude`와 `codex`는 저장소 MCP 서버
  (`repo_mcp.py`). `ops` 프로젝트는 읽기 전용 ```ops 점검(`ops_checks.py`). `patch`, 액션 블록, `jev_mcp`는 없다.
- **세션 하나, 여러 턴.** 검색 후속 질의(저장소 결과, 인용 보정)는 토론 한 턴과 똑같이 호출 안에서 일어나므로 답은
  토론 초안만큼 근거를 갖는다. 고쳐 줄 두 번째 에이전트는 없다.
- **판정자 없음**은 평결이 없다는 뜻이다. 답에는 `SOLO` 라벨이 붙는다 (`PASSED`, `APPROVED`, `UNVERIFIED`는 공통
  마감의 평결이므로 쓰지 않는다). 라벨은 결과가 보이는 모든 곳에 따라간다.

## 닫아 두는 것

답을 효과로 바꾸는 경로는 모두 플래그가 아니라 구조상 닿을 수 없게 한다.

| 경로 | 닿을 수 없는 이유 |
|---|---|
| 액션 (`apply_patch`, `execute_code_action`, `ops:*`, 일괄 계획) | 단독 프롬프트에 액션 규약이 없고 결과에서 액션 블록을 읽지 않는다. 블록이 나와도 글로만 남고 무시된다. |
| jev 게이트, 투표, 자동 적용, 자동 실행 | 라운드의 공통 마감에서만 돌고, 단독 실행은 거기에 들어가지 않는다. |
| 설계 산출물 (`jev_mcp:write_artifact`) | 도구를 붙이지 않는다. |
| 플릿 쓰기 | 단독 ops 접근은 읽기 전용 점검 묶음뿐이다. `/api/exec`, 명령 묶음, 스크립트 없음. |
| 다른 호스트의 자격 증명 | 워커처럼 실행하는 호스트의 자격 증명만 쓴다. |

시험(`test_solo_agent.py`)이 이 목록을 고정한다. 단독 프롬프트에는 액션 규약 문구가 하나도 없고, 실행기는 쓰기
도구를 넘기지 않으며, 위조한 액션 블록이 있는 결과도 액션 행을 만들지 않는다.

## 실행 모양

- CLI: `guardian.py --agent-run 질문 [--project ID] [--role 페르소나] [--provider 이름] [--context-path GLOB]
  [--context-ref REF] [--result-file PATH] [--events-file PATH] [--json]`. 프로젝트, 작업 클론, 컨텍스트 플래그는
  `--debate`와 같다. `--provider`는 공급자 하나를 지정하고, 없으면 쓸 수 있는 첫 공급자가 돌며 실패하면 토론
  구성원처럼 다음 공급자로 넘어간다.
- **저장.** 스레드도 `debate-jobs` 행도 없다. `<GUARDIAN_DATA_DIR>/solo-runs/<id>/` 아래 기록 하나에
  `result.json`(질문, 역할, 공급자, 커밋 sha, 답, 검사 결과, 시간, `label: "SOLO"`)과 `events.jsonl`을 둔다. 기록은
  30일 뒤 만료된다 (`--solo-prune`, 기존 ops-watch 타이머가 실행).
- **동시성.** 자기 슬롯 `GUARDIAN_MAX_SOLO`(기본 2)를 쓴다. 토론, 감사와 분리해서 질문이 긴 작업 뒤에서 기다리지
  않고, 질문이 몰려도 운영 토론을 굶기지 못한다. 세 번째 실행은 줄 세우지 않고 "busy"로 거부한다.
- **세션.** 실행마다 새 세션이다. 이어 갈 스레드가 없다. (후속 질문은 새 실행이며, 사람이 앞선 답을 컨텍스트 글로
  붙여 넣을 수 있다.)

## 답에 대한 검사

판정자가 없으니 남는 것은 값싼 결정적 검사다.

- **인용 검사** (`evidence.py`, 줄 범위 규칙): 답이 인용한 `path:line`은 세션에 보여 준 줄 안에 있어야 한다. 결과는
  인용마다 `verified`, `unshown`, `missing`을 적고 요약 줄이 개수를 알려 준다. 토론 초안이 통과하는 검사와 같고
  여유값(`GUARDIAN_CITATION_SLACK`)도 같다.
- **비밀.** `is_secret`이 토론과 같이 모든 경로 구성요소에 적용되어 `*.enc` 파일이나 자격 증명 묶음은 읽을 수 없다.
- **공급자 대체.** 모든 공급자가 실패하면 결과에 대체 응답과 `label: "SOLO"`, `degraded: true`가 붙는다
  (토론 라운드의 unverified 표시와 같은 뜻이지만 평결로 읽히지 않는 이름).

모델은 답에 점수를 매기지 않는다. 두 번째 의견이 필요하면 답을 토론으로 넘긴다 (아래 `Run as debate`). 단독 실행이
그것을 하지는 않는다.

## 보이는 곳

- **CLI.** 머리글 `SOLO answer (unverified, no Judge)`, 인용 요약, sha가 붙은 평문.
- **API.** `POST /api/solo` (`{question, project, role?, provider?, context_paths?}` -> `{id}`, Go 처리기가 토론처럼
  CLI를 띄운다), `GET /api/solo/{id}`, `GET /api/solo` (최근 순). 인증은 기존 전역 체인이고 토큰별 속도 제한은
  토론과 같다.
- **대시보드 (S3).** 업무 흐름 화면의 "빠른 질문": 입력 상자, 프로젝트와 역할 선택, 라벨 칩과 인용 개수가 붙은 답.
  끝난 답에는 버튼 둘: **토론으로 실행**(질문, 프로젝트, 답을 참고 글로 새 토론 양식에 채워 공통 마감이 검증하게
  함)과 **복사**. 문자열은 언제나처럼 두 카탈로그(`ko`, `en`)에 넣는다.
- **업무 흐름 목록.** 단독 실행은 토론이 아니므로 토론과 함께 나열하지 않고 자기 짧은 목록을 갖는다.

## 읽기 단계: 승인 게이트 없음, 카탈로그만

단독 실행이 승인을 요구하지 않는 이유는 할 수 있는 일이 모두 읽기이고, 이 저장소가 이미 읽기를 그렇게 다루기
때문이다 (`ops_checks.py`의 ```ops 점검은 승인 없이 돌고 `source=ops_check`로 기록되며, 저장소 도구에는 게이트가
없다). 안전은 게이트가 아니라 "읽기"를 어떻게 정하느냐에서 나온다.

- **분류기가 아니라 카탈로그.** 읽기는 이름 있는 항목(`df`, `journal_tail`, `service_status`, `list_dir` 등)이며 인자는
  타입으로 검증하고, 셸 문자열이 아니라 argv 목록으로 실행한다. 자유 입력 명령은 "읽기 전용"으로 판정하지 않는다.
  읽기처럼 보이지만 쓰는 모양(`find -exec/-delete`, `sed -i`, `sort -o`, `tee`, `xargs`, 리다이렉션, 셸로의 파이프,
  `awk system()`, `git` 훅과 페이저, `curl -o`)은 패턴으로 믿을 만하게 가를 수 없다. 카탈로그 밖 명령은 단독
  에이전트가 실행하지 않고 일반 승인 경로로 간다.
- **게이트 없이도 남기는 것.** 감사 줄(`source=ops_check`), 경로 거부 규칙(`is_secret`, `*.enc`, 자격 증명 묶음,
  `/etc/shadow`; 읽기에도 적용), 시간 제한과 출력 크기 상한, 사람이 고른 호스트 범위.
- **읽기는 유출 경로다.** 출력이 모델 컨텍스트로 들어가므로 비밀이 공급자에게 갈 수 있다. 환경 전체나 설정 트리를
  덤프하는 항목은 카탈로그에 넣지 않으며, 거부 규칙과 마스킹은 유지한다.
- **카탈로그 확장**은 별도 변경이다. 새 항목마다 위의 쓰기 모양 목록에 대해 시험으로 확인한다.

이 문서의 범위 밖: 상태를 바꾸는 명령 실행. 사람이 입력한 명령, 또는 에이전트가 제안하고 사람이 승인한 명령은 기존
경로(`/api/exec`, 명령 묶음, `ops:run_script`)와 그 결정적 가드(`deny_commands`, 우회 모양, 보호 유닛·패키지, `STALE`,
감사)를 쓴다. 둘 다 LLM 판정자가 필요 없다. 결정자가 이미 사람이고, 모델이 짐작만 할 부분은 결정적 가드가 맡는다.
판정자와 jev 게이트는 무엇을 해야 하는지 불분명한 열린 질문(`fleet` 토론)을 위해 남는다.

## 진입점: CLI와 스킬

- **CLI** `guardian.py --agent-run`이 메커니즘이다 (기록, 슬롯, 인용 검사, 닫힌 경로).
- **스킬**은 LLM CLI나 말로 시작하는 사람을 위한 입구다. `deploy/llm-skills/` 아래 얇은 스킬 하나(예: `guardian-ask`)가
  "X는 어디 있나 / Y는 무엇을 하나"를 `--agent-run`으로 잇고 라벨을 출력한다. 자기 논리나 도구는 없다. 기존
  구분을 따른 것이다. `guardian-host-check`는 이미 판정자 없는 읽기 전용 단일 에이전트의 스킬 형태이고,
  `guardian-fleet-ops`는 토론의 입구다. 읽기 카탈로그는 스킬의 점검과 `ops_checks.py`가 함께 써서 어긋나지 않는다.
- **스킬로 만들지 않는 것:** 독립성이나 보증이 필요한 것(검토자, 판정자, 게이트). 스킬은 에이전트 하나에게 주는
  지시이고 아무것도 강제하지 않는다. 그런 것은 흐름 템플릿(`flow-templates.ko.md`)이다.

## 단계

- **S1 엔진, CLI, 스킬.** `solo_agent.py`(새 파일, 작음): 페르소나로 세션을 만들고, 기존 `_ask` 수준의 장치로 호출 한
  번을 돌리고, 인용 검사를 적용하고, 기록을 쓴다. `guardian-ask` 스킬과 공용 읽기 카탈로그도 함께 만든다. 토론 경로와 가깝게 두려고 `DebateEngine`의 에이전트 호출(repo 블록
  순환, `McpTurn`, 공급자 대체)을 복사하지 않고 재사용한다. 결합이 어색하면 첫 단계에서 그 호출을 둘이 함께 쓰는
  함수로 뽑고 골든 관문을 통과시킨다. 시험: 닫힌 경로 목록, 인용 라벨, 공급자 대체, 가짜 LLM, 임시 데이터
  디렉터리(`testenv.isolate_data_dir()`).
- **S2 API.** Go 경로, 슬롯, ops-watch 서비스의 만료 정리, `GET` 목록. 대시보드 없음.
- **S3 대시보드.** 빠른 질문, 결과 화면, 토론으로 실행, 두 카탈로그 문자열.

S1-S2에서는 기존 역할의 프롬프트가 바뀌지 않으므로 `RETRIEVAL_PROMPT_VERSION`은 그대로이고, 단독용 덧붙임 글은
자기 버전 상수(`SOLO_PROMPT_VERSION`)를 가진다.

## 제안하는 결정 (운영자의 확인 필요)

1. **라벨.** 평결처럼 보이는 상태 대신 `SOLO`와 눈에 보이는 문구 "unverified, no Judge".
2. **ops 프로젝트.** 읽기 전용 점검 묶음(토론 에이전트가 가진 것과 같음)만 허용한다. 무언가를 실행해야 하는
   플릿 질문은 계속 `fleet` 토론으로 간다.
3. **저장.** 스레드가 아니라 30일 만료인 별도 `solo-runs/` 기록. 결정 DB에 닿지 않고 평결로 "이어질" 수 없다.
4. **슬롯.** `GUARDIAN_MAX_SOLO` 기본 2.
5. **v1에는 모델이 매기는 평가 없음.** 두 번째 의견은 "토론으로 실행"이 담당한다.
6. **일반 모드 (2026-10-30 결정, "질문 + 프로젝트" 모델을 고친다).** 프로젝트 없이도 질문할 수 있다: `general: true`(CLI
   `--general`), 프로젝트, context path, ref와 함께 쓸 수 없다. 모델의 일반 지식만으로 답한다. `zai`(코드 작업용으로 켠 외부
   엔드포인트)를 뺀 모든 provider가 답할 수 있다. 첫 버전은 모든 도구를 끈 채 도는 `claude`뿐이었으나 운영자가 같은 날
   "외부 도구를 쓰지 못하는 것이 필수는 아니다"라며 넓혔다. 그래서 `codex`, `agy`는 내장 도구를 가진 채 답할 수 있고
   "출처 없음"은 보장이 아니라 표시다. 저장소, ops 점검, 위키는 붙지 않는다. 결과의 라벨은 늘 그렇듯 `SOLO`이고 "unverified, no Judge, no
   sources"라고 적는다. 닫아 둔 경로는 그대로다(실행할 수 있는 것은 아무것도 붙지 않는다).

## 열린 점

- 운영 토론과 공유하는 Codex 한도 때문에 단독 실행에 일일 상한이 필요한지: 먼저 재고 정한다.
- `--agent-run`이 팀 구성원처럼 워커 호스트(`host`)를 받을지. S1에는 넣지 않는다. 워커 설계는 이미 역할 하나를 상태
  없이 돌리며, 워커의 단독 실행은 스냅샷 규약이 필요하다. 요청이 있을 때만 더한다.
- 시작할 때 입력한(저장하지 않는) 페르소나 글을 허용할지. S1에는 넣지 않는다. 저장된 페르소나는 검토할 수 있지만
  입력한 글은 그럴 수 없다.

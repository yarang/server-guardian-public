# 데스크톱 내보내기 폴더

[English](desktop-export.md) | 한국어

상태: **2026-11-24 삭제**([ui-verification-review.ko.md](ui-verification-review.ko.md)의 UD3, 운영자 승인): 수동·자동 내보내기
폴더를 대시보드와 데스크톱 셸(`export.rs`, dialog 플러그인)에서 없앴다. 셸은 Markdown용 `save_download`를 그대로 둔다.
이 문서의 나머지는 삭제된 기능의 설명이다. 이전: 2026-10-25 승인(아래 "보완"으로 표시한 수정 포함), 당시 구현 없음. 운영자가 데스크톱 앱에서 결과물을 원하는 디렉토리에
정리해서 저장하는 방안을 요청했다. 결정은 5장에 있고, 자동 내보내기(E3)가 범위에 들어간다(수동 우선 권장안과 다른 결정).

## 1. 문제

지금 데스크톱 셸(Tauri)이 쓸 수 있는 것은 OS 다운로드 폴더에 Markdown 파일 하나를 저장하는 것뿐이다
(`save_file.rs::save_download`). 스레드 보고서에는 다운로드 버튼이 있고(`ReportButton.tsx`), 산출물 파일에도 있다
(`ArtifactsTab.tsx`, Markdown만 가능하고 `.mmd`와 `.svg`는 셸에서 거부된다). 한 토론의 결과가 `thread_ab12.md` 같은
이름의 낱개 파일로 다른 파일과 같은 폴더에 섞이고, 프로젝트별로 결과를 모아 둘 방법이 없다.

## 2. 하는 일

**내보내기 루트**(네이티브 폴더 선택창)를 한 번 고르면, "폴더에 저장"이 그 아래에 고정된 배치로 결과를 쓴다.

```
<루트>/
  <프로젝트>/
    <스레드>/
      report.md                 토론 보고서, 자산 포함 (다운로드 버튼이 만드는 것과 같은 본문)
      v<n>/<산출물 파일>         그 스레드의 디자인 산출물, 저장된 버전마다 폴더 하나
```

원본은 모두 이미 읽기 전용 API가 주고 결과 탭이 보여 주는 것이다(`docs/design/project-results.ko.md`).

- 스레드 보고서 (`GET /api/threads/{thread}/report`)
- 디자인 산출물 (`GET /api/threads/{thread}/artifacts`, `.md`, `.mmd`, `.svg`)

진입점은 둘이다. 결과 행 / 보고서 대화상자 / 산출물 버전의 "폴더에 저장", 그리고 결과 탭의 "이 프로젝트 전체 저장"
(이미 있는 것은 건너뛴다). 범위 밖: 감사 보고서, 액션·계획 패널, 코드 위키 페이지, 허브로의 쓰기. 브라우저 빌드는 지금의
Blob 다운로드를 그대로 쓰고 폴더 버튼을 보이지 않는다.

## 3. 설계

### 3.1 웹뷰는 경로를 정하지 못한다

지키고 싶은 보안 성질: 페이지가 침해되어도(렌더된 Markdown의 저장형 XSS 등) 운영자가 고른 폴더 밖에는 쓸 수 없다.

- 폴더 선택창은 **Rust**가 연다(`export_choose_root`). 웹뷰는 표시용 경로만 돌려받는다.
- 루트는 Rust가 앱 설정 디렉토리(`export.json`)에 저장한다. `localStorage`도 웹뷰도 아니다.
- 쓰기 명령은 `project`, `thread`, `{ rel_path, contents }` 목록만 받고, 경로는 저장된 루트 아래에서 Rust가 만든다.
  웹뷰는 루트나 절대 경로를 넘길 수 없다.

### 3.2 명령 (새 모듈 `export.rs`, `main.rs`에 등록)

| 명령 | 동작 |
|---|---|
| `export_get_root()` | 저장된 루트. 없거나 더 이상 존재하지 않으면 `null` |
| `export_choose_root()` | 네이티브 폴더 대화상자, 선택을 저장하고 반환. 취소하면 `null` |
| `export_clear_root()` | 루트를 잊는다 (폴더와 파일은 그대로) |
| `export_save(project, thread, files)` | 파일을 쓰고 파일별 `{written, skipped, renamed}`를 반환 |
| `export_reveal()` | OS 파일 관리자에서 루트를 연다 (루트 경로만) |

`tauri-plugin-dialog`는 **Rust에서만** 쓴다(`app.dialog().file().pick_folder`). 웹뷰에는 dialog·fs 권한을 주지 않으므로
기본값 이상의 `capabilities` 파일이 필요 없고 CSP도 바뀌지 않는다. 네이티브 선택창의 대가는 새 의존성(`rfd`를 끌어온다)이며,
`rfd`를 직접 쓰는 대안도 무게는 같다.

### 3.3 경로 안전 (`save_file.rs`를 재사용하고 더 조인다)

- `project`는 `^[a-z0-9][a-z0-9_-]{0,63}$`, `thread`는 `^thread_[A-Za-z0-9_]{1,80}$` (허브와 같은 패턴). `rel_path`는
  `/`로 나눠 모든 구성요소가 `^[A-Za-z0-9][A-Za-z0-9._-]{0,80}$`를 만족해야 하고, `..`·빈 구성요소 금지, 깊이 최대 3,
  확장자는 `md`, `mmd`, `svg`만.
- Windows 예약 이름(`CON`, `NUL`, `COM1` ...)과 끝의 점은 거부해서 같은 내보내기가 모든 OS에서 되게 한다.
  보완: 검사는 확장자를 뗀 이름(stem) 기준이라 `CON.md`, `NUL.svg`도 거부하고, 이름은 대소문자를 구분하지 않고 비교한다
  (macOS와 Windows는 `Report.md`와 `report.md`를 같은 파일로 본다). 충돌 검사에도 똑같이 적용한다.
- 허브와 대조함(2026-10-25): 저장된 산출물 이름은 평평하고 소문자다(`artifact_ops.NAME_PATTERN`
  `[a-z0-9][a-z0-9._-]{0,80}`, 확장자 `.md`, `.mmd`, `.svg`). 위 구성요소 규칙의 부분집합이므로 `v<n>/<이름>`은 깊이 2로
  한도 3 안에 든다.
- 위협 모델: 검사와 쓰기 사이에 로컬 공격자가 디렉토리를 심볼릭 링크로 바꾸는 경우는 범위 밖이다(임시 이름 후 rename으로
  창을 좁힌다). 지키는 성질은 웹뷰가 경로를 고를 수 없다는 것이다.
- 디렉토리는 구성요소 하나씩 `symlink_metadata`로 확인하며 만들고, 루트 아래 어디든 심볼릭 링크는 거부한다. 최종 경로가
  정규화된 루트로 시작하는지 확인한다.
- 파일당 16 MiB(`save_download`와 같음), 호출당 64 MiB·500개.
- 같은 폴더의 임시 이름에 쓴 뒤 rename한다(쓰다 만 결과를 남기지 않음).

### 3.4 충돌

저장된 산출물 버전은 바뀌지 않으므로 두 번 내보내도 중복되면 안 된다. 스레드 보고서는 바뀔 수 있다(이어서 토론하면 허브에서
라운드가 붙고 보고서를 덮어쓴다). 규칙: 덮어쓰지 않는다. 대상이 같은 바이트로 이미 있으면 `skipped`, 다르면 `save_download`처럼
`report (1).md`로 옆에 쓴다. 이전 사본은 모두 남고, 필요 없는 것은 운영자가 지운다.

보완: 비교 대상은 기본 이름**과 접미사가 붙은 모든 변형**(`report (1).md`, `report (2).md` ...)이다. 하나라도 같은
바이트면 `skipped`, 아니면 비어 있는 다음 접미사를 쓴다. 이 규칙이 없으면 바뀐 보고서를 두 번 내보낼 때 두 번 저장되어
"전체 저장"과 자동 내보내기가 멱등하지 않다.

### 3.5 대시보드

- 결과 탭과 보고서 대화상자는 데스크톱 셸에서만 내보내기 루트("폴더 선택")와 저장 버튼을 보이고, 결과는 쓴/건너뛴/이름 바꾼
  파일 수와 "폴더 열기"를 안내한다.
- 설정에 "내보내기 폴더" 행(현재 경로, 변경, 잊기)을 둔다.
- 새 문구는 `src/i18n/ko`와 `src/i18n/en` 둘 다에 넣는다. 셸 감지는 기존대로 `'__TAURI_INTERNALS__' in window`.
- `ArtifactsTab.saveArtifact`는 낱개 Markdown에는 `save_download`를 유지하고, 루트가 있으면 내보내기를 쓴다. 그러면
  `.mmd`·`.svg`의 "셸은 Markdown만" 제약도 풀린다.

### 3.6 테스트

경로 규칙 Rust 단위 테스트(상위 경로, 절대 경로, 예약 이름, 깊이, 잘못된 확장자, 루트 아래 심볼릭 링크, 사라진 루트, 같은
내용 재내보내기, 다른 내용 재내보내기, 크기 한도)를 임시 디렉토리에서 돌린다. 웹 테스트는 `invoke`를 모의해 버튼을 확인한다.
`scripts/ci.sh`는 tauri 섹션을 이름을 줄 때만 실행한다(`scripts/ci.sh tauri`).

### 3.7 자동 내보내기 (E3)

범위에 넣기로 결정했고(D3), 동작은 2026-10-25에 운영자가 확인했다. 경로 규칙과 덮어쓰지 않는 규칙은 `export_save`와
같고, Guardian이 직접 쓴 파일에 한해 좁은 예외가 하나 있다(아래). Rust 명령 `export_auto_get`, `export_auto_set`,
`export_auto_marks`, `export_auto_recent`, `export_auto_save`가 더해진다.

- **선택 사항.** 설정의 스위치 "새 결과 자동 저장", 기본 꺼짐, 루트가 있을 때만 쓸 수 있다. 값은 웹뷰가 아니라 Rust가
  루트 옆(`export.json`)에 저장한다. 루트를 지우면 스위치도 꺼진다.
- **트리거.** 끝난 토론 중 상태 단어가 `APPROVED` 또는 `DISPUTED`(결과 탭이 가진 원래 단어이며, 이 절의 초안은 앞의 것을
  `PASSED`라고 불렀다)이고 현재 `updated_at`으로는 아직 내보내지 않은 것. 진행 중, 실패, 취소된 결과는 자동으로
  내보내지 않고 한 번의 클릭으로 저장한다.
- **시작 시점.** 켠다고 과거 결과를 채워 넣지 않는다. `updated_at`이 스위치를 켠 시각 이후인 결과만 내보낸다. 과거
  결과는 "이 프로젝트 전체 저장"으로 채운다.
- **실행 위치.** 앱이 켜져 있는 동안 대시보드에서, 시작할 때 한 번 그리고 30초마다. 앱이 꺼져 있으면 아무것도 내보내지
  않고, 다음 시작 때 그사이 끝난 것 중 스위치를 켠 뒤에 끝난 것을 내보낸다.
- **갱신인가 중복인가.** 이어서 토론한 스레드는 보고서가 바뀐다. `report.md`가 Guardian이 마지막에 쓴 내용의 해시와 같으면
  그 자리에서 교체한다(`updated`). 운영자가 고쳤다면 그대로 두고 새 내용은 `report (1).md`로 쓴다(`renamed`). Guardian이
  기록하지 않은 파일은 갱신하지 않으며, 번호가 붙은 사본이 갱신 대상이 되는 일도 없다. 산출물 버전 `v<n>/...`은 불변이라
  같으면 건너뛴다. 수동 저장은 단순 덮어쓰지 않음 규칙을 유지한다(기록에는 남기지만 갱신하지 않는다).
- **기록.** Rust가 `export.json`에 내보낸 파일별 해시(기본 이름 자리에 마지막으로 쓴 내용)와 스레드별 마커(내보낸 결과의
  `updated_at`)를 둔다. 대시보드는 마커만 비교하고 폴더를 읽지 않으며, 해시는 Rust가 제자리 갱신 여부를 가릴 때만 쓴다.
  루트를 바꾸거나 지우면 둘 다 잊는다. 이전 폴더에 대한 기록이기 때문이다.
- **가시성.** 자동 저장마다 쓴 개수와 "폴더 열기"가 있는 알림을 보이고, 최근 20건을 설정 행에 나열한다. 디스크에 쓰는
  일이 조용히 일어나지 않는다. 내보내지 못한 결과는 주기마다 다시 시도하지 않고, `updated_at`이 바뀌거나 앱을 다시 켜면
  시도한다.

## 4. 단계

- **E1** 루트 명령과 `export_save`, Rust 테스트(보완한 충돌·예약 이름 경우 포함), 설정 행.
- **E2** 결과 탭 / 보고서 대화상자 / 산출물 버튼, "프로젝트 전체 저장", 셸에서 `.mmd`·`.svg`.
- **E3** 자동 내보내기(3.7): 스위치, `APPROVED`/`DISPUTED` 트리거, 고치지 않은 보고서의 제자리 갱신, 알림과 최근 목록.

## 5. 결정

2026-10-25 결정: D1 권장안대로. D2·D3는 범위를 보고서와 디자인 산출물로 하고 수동(E1-E2)**과** 자동(E3)을 모두 한다.
D4-D6은 권장안대로. 아래 각 항목의 본문은 처음 제안한 내용이다.

- **D1 배치.** 권장: 위의 `<루트>/<프로젝트>/<스레드>/...`. 대안: 날짜 단계(`2026-10/`) 또는 폴더 이름에 제목 슬러그(읽기
  좋지만 제목은 모델 출력이라 강하게 정리해야 한다. 스레드 id는 `thread.json`에 따로 둔다).
- **D2 "정리"의 범위.** 권장: 보고서와 디자인 산출물만. 대안: 계획·감사 보고서도(허브에 아직 파일 형태가 없다), 또는 프로젝트별
  `index.md`에 내보낸 스레드 목록.
- **D3 수동/자동.** 권장: 먼저 수동(E1-E2). 새로 승인된 결과의 자동 내보내기는 대시보드 폴링에서 돌아 클릭 없이 디스크에 쓰고,
  앱이 켜져 있을 때만 동작한다.
- **D4 충돌.** 권장: 덮어쓰지 않고 다른 보고서는 접미사. 대안: 보고서는 덮어쓰고 산출물 이력만 유지.
- **D5 루트 하나/프로젝트별.** 권장: 하나. 프로젝트별 루트는 저장·복구할 매핑이 늘어난다.
- **D6 의존성.** 권장: `tauri-plugin-dialog`를 Rust에서만 사용. 대안: `rfd`.

## 6. 구현 메모

### E1 (2026-10-25)

설계대로 만들었고, 설계에서 열어 둔 부분과 달라진 점은 다음과 같다.

- **결과 모양.** `export_save`는 파일마다 `{ relPath, outcome, savedAs }`를 camelCase(serde `rename_all`)로 돌려준다.
  `outcome`은 `written`, `skipped`, `renamed`이고 `savedAs`는 최종 상대 경로다(이름이 바뀌었으면 접미사가 붙은 이름,
  건너뛰었으면 이미 있는 파일). 같은 이유로 입력 목록도 `{ relPath, contents }`다(설계 본문의 `rel_path`와 다르다).
- **순수한 핵심.** 검사와 쓰기는 모두 Tauri를 쓰지 않는 `save_files(root, project, thread, files)`에 있다. `export_*`
  명령은 `export.json`에서 루트를 찾아 이 함수를 부를 뿐이라, Rust 테스트(내보내기 모듈 17개, 크레이트 전체 20개)는 앱
  핸들 없이 돈다.
- **설정 파일.** 앱 설정 디렉터리의 `export.json`에 `{ "root": ... }`를 두고 `#[serde(flatten)]`으로 모르는 키를
  보존한다. E3가 필드(스위치, 해시 기록)를 더해도 마이그레이션이 필요 없고 루트도 잃지 않는다. 쓸 때는 임시 파일 후
  이름 바꾸기로 원자적으로 쓴다.
- **루트 검사.** `export_choose_root`는 드라이브·파일시스템 루트를 거부하고 정규화한 경로를 저장한다.
  `export_get_root`는 저장한 폴더가 없어졌으면 `null`을 준다. 루트 자체가 심볼릭 링크면 쓸 때 하위의 링크와 똑같이
  거부한다.
- **호출 전체를 먼저 검증.** 경로, 확장자, 크기, 한 호출 안의 중복까지 전체 목록을 확인한 뒤에야 쓰기 시작하므로, 잘못된
  항목이 있으면 일부만 내보낸 상태를 남기지 않고 호출 전체를 거부한다.
- **`export_reveal`**은 저장한 루트에만 `open`(macOS), `explorer`(Windows), `xdg-open`(그 밖)을 실행한다.
- **대화상자 플러그인.** `tauri-plugin-dialog`는 `main.rs`에 등록하지만 Rust에서만 부른다(async 명령 안의
  `blocking_pick_folder`). capabilities 파일은 그대로다. 빌드가 `gen/schemas/*`와 `Cargo.lock`을 다시 만들었고, 둘 다
  추적 파일이라 E1과 함께 커밋한다.
- **대시보드.** `ExportFolderSection`(설정의 허브 연결 구역)은 `__TAURI_INTERNALS__`가 있을 때만 `lib/exportFolder.ts`를
  거쳐 그려지고, Rust에 경로를 넘기지 않는다. 문구는 두 카탈로그의 `shell.exportFolder`에 있다. 저장 버튼은 E2에서 더한다.

### E2 (2026-10-25)

대시보드만 바꿨고 Rust는 그대로다. 설계와 달라지거나 열려 있던 부분은 다음과 같다.

- **스레드당 한 번의 호출.** `exportThread(project, thread, {report, artifacts})`(`lib/exportThread.ts`)는 `report.md`와
  살아 있는 버전마다 `v<n>/<파일>`을 만들어 `export_save` 한 번으로 보낸다. Rust가 호출 전체를 먼저 검증하므로 스레드는
  전부 아니면 전무다. 요청한 프로젝트와 `project`가 다른 보고서나 버전 목록은 아무것도 보내기 전에 거부한다.
- **전체 저장.** `exportProject`는 목록의 결과를 한 번에 한 스레드씩 처리해(메모리가 일정하고 진행률이 고르다) 실패를
  `{thread, message}`로 모으고 계속 간다. 알림에는 새로 쓴 것, 건너뛴 것, 이름을 바꿔 쓴 것의 개수와 실패한 스레드가
  나온다. 보고서나 산출물 버전이 있는 결과만 방문한다.
- **건너뛰는 것.** 만료된 버전과 파일, 셸이 저장하지 못하는 종류(md/mmd/svg가 아닌 것)는 조용히 빼며 실패로 치지 않는다.
- **행별 버튼 없음.** 결과 행은 앵커라 그 안에 버튼을 두면 잘못된 중첩이다. 한 스레드는 상세 화면의 "이 결과를 폴더에
  저장"이, 프로젝트 전체는 목록 위의 "프로젝트 전체를 폴더에 저장"이 맡는다.
- **보고서 보기.** `ReportView`에 `exportable`(기본 켜짐)을 더했다. 결과 상세는 자체 "이 결과를 폴더에 저장"이 있어 끈다.
  기존 "MD 다운로드" 버튼은 그대로다.
- **산출물 다운로드.** 셸에서 루트가 있으면 파일 뷰어의 다운로드가 내보내기 폴더에 `v<n>/<경로>`로 쓰고 전체 경로를
  알려 준다. 루트가 없으면 Markdown은 예전처럼 `save_download`로 다운로드 폴더에 가고, 다른 종류는 `desktopMarkdownOnly`로
  실패한다(이 문구에 설정에서 폴더를 고를 수 있다는 안내를 넣었다). 살아 있는 버전의 파일 목록에는 "이 버전을 폴더에
  저장" 버튼이 있다.
- **루트는 필요할 때.** `useExportAction`(`components/ExportButton.tsx`)은 먼저 루트를 묻고, 저장한 것이 없으면 폴더
  대화상자를 연다. 취소하면 아무것도 쓰지 않는다. 셸 밖에서는 버튼을 그리지 않는다.
- **테스트.** `tests/exportSave.test.tsx`(11개)가 `invoke`와 허브 API를 모의한다. 페이로드 모양, 다른 프로젝트 거부,
  실패한 스레드가 나머지를 막지 않음, 만료 버전을 가져오지 않음, 셸 밖에는 버튼이 없음, 다운로드 경로 선택을 확인한다.

### E3 (2026-10-25)

Rust와 대시보드를 바꿨다. 위 3.7절은 운영자가 확인한 동작에 맞게 고쳤고, 설계와 달라지거나 열려 있던 부분은 다음과
같다.

- **장부와 마커.** `Config`에 `auto`, `autoSinceMs`, `hashes`(`<프로젝트>/<스레드>/<상대경로>` -> 기본 이름 자리에
  Guardian이 마지막에 쓴 내용의 FNV-1a 64), `marks`(`<프로젝트>/<스레드>` -> `updated_at`), `recent`(20건)가 생겼고
  모르는 키는 여전히 보존한다. FNV-1a는 보안 해시가 아니다. "이 파일이 내가 쓴 그대로인가"만 알아보며, 파일을 일부러 옛
  해시와 충돌하게 고쳐도 얻는 것이 없다.
- **결과 하나 추가.** `written`, `skipped`, `renamed`에 `updated`가 더해졌다. `export_save`는 이를 돌려주지 않고
  `export_auto_save`만 돌려준다. `place_file`은 `recorded`와 `update`를 받으며, 기본 이름만 바꿀 수 있고 현재 해시가
  기록과 같을 때만 바꾼다.
- **직렬화.** 설정과 폴더의 모든 읽기와 쓰기는 `EXPORT_LOCK` 하나를 거친다. 30초 주기와 수동 저장이 `export.json`의
  읽고-고치고-쓰기를 서로 끼어들지 못한다.
- **빈 실행은 조용하다.** 자동 저장이 성공할 때마다 마커는 기록하지만, `Recent` 항목과 대시보드 알림은 쓰거나, 이름을
  바꾸거나, 갱신한 것이 있을 때만 생긴다. 전부 건너뛴 실행은 알릴 일이 아니다.
- **스위치 상태는 계산한다.** `export_auto_get`은 루트가 있을 때만 `enabled`를 돌려주므로, Guardian 밖에서 폴더를 지워도
  스위치가 켜진 것처럼 보이지 않는다.
- **실행기.** `AutoExport`(`components/AutoExport.tsx`)는 `AppStores`가 프로젝트 스토어 아래에 마운트하고, 셸 밖에서는
  아무 일도 하지 않으며, 선택한 프로젝트만이 아니라 프로젝트 목록 전체를 훑는다. 재진입 가드가 겹치는 주기를 막고,
  `AuthRequiredError`를 비롯한 실패는 그 주기만 조용히 끝낸다. 알림은 닫을 수 있는 고정 상자다(대시보드에 토스트
  컴포넌트가 없다). 창 이벤트 `guardian:auto-export`로 설정의 목록을 다시 불러온다.
- **`threadFiles`.** 수동 저장과 자동 저장이 같은 파일을 만들도록 `exportThread`에서 분리했다.
- **테스트.** Rust는 `export.rs`에 24개, 크레이트 전체 27개(새로: 제자리 갱신, 고친 보고서 유지, 수동 저장은 갱신하지 않지만 장부에 남김,
  기록이 없으면 갱신 안 함, 번호 붙은 사본은 갱신 안 함, 해시 값, 설정 기본값). 대시보드는 `tests/autoExport.test.tsx`
  (11개: 상태, `since`, 마커, 내용에 따른 대상 판정, 스위치 꺼짐, Rust로 마커 전달, `updated` 집계, `updated_at`이 바뀌기
  전에는 실패를 다시 시도하지 않음, 알림과 "폴더 열기", 셸 밖과 꺼진 동안의 침묵)와
  `tests/exportFolder.test.tsx`의 스위치 테스트 3개.
- **하지 않은 것.** 앱이 켜진 채 토론이 끝나는 전체 경로를 실제 데스크톱에서 돌려 보지는 않았다. 검증은 모의 `invoke`와
  Rust 단위 테스트다.

[English](ui-verification-review.md) | 한국어

상태: 2026-11-23 제안. UD1, UD2, UD4, UD5, UD6을 운영자가 같은 날 승인했다. UD3(데스크톱 내보내기 폴더 삭제)은
2026-11-24 승인. U0-U3는 2026-11-23 `e9a939a`로 배포, X3은 2026-11-24 구현, 배포 안 됨.
출발점: [verification-layer.ko.md](verification-layer.ko.md)의 DP1(Guardian은 에이전트 개발 환경이 아니라 검증·통제
계층이자 fleet 운영 도구). 이 문서는 그 포지셔닝에 비추어 대시보드를 점검한다: 더는 자리값을 못 하는 기능, 일상 작업
사이에 끼어 있는 설정, 빠른 리뷰에 필요한 화면. 메뉴 자체(목적지 다섯 개, `ui-flow-redesign.md`)는 유지한다.

## 현재 구성 (2026-11-23, `apps/web-desktop/src`)

| 목적지 | 탭과 섹션 |
|---|---|
| 현황 | 허브, SSH, 승인, 토론 패널 |
| 노드 | 노드, 그룹, SSH, 명령, 명령 세트 |
| 작업 흐름 (프로젝트별) | 토론, 빠른 질문, 상주 에이전트, 흐름 종류, 위키(code) 또는 산출물(design), 결과. 페르소나는 숨은 경로 `#/debates/personas` |
| 승인 | 제안된 action과 plan |
| 설정 | 허브 연결, 흐름 설정(프로젝트, 팀, 페르소나), 실행 환경(worker), 표시(언어, 데스크톱 내보내기 폴더) |

발견:

1. **팀이 결정보다 오래 남았다.** `flow-graph.md`의 D7(2026-11-01 결정): "흐름이 팀과 템플릿을 대신한다 ... 팀 계층은
   없어진다". 대시보드에는 아직 팀 편집기(설정 -> 팀, `TeamsSection.tsx` + `TeamDialog.tsx`, 약 790줄), 작업 흐름의
   "팀 관리" 링크, 시작 폼에서 흐름 선택기 옆의 팀 선택기가 있다. 한 토론의 구성을 고르는 길이 두 개다.
2. **페르소나를 두 곳에서 편집한다.** 전체 편집 페이지(`pages/personas/`, 작업 흐름에서 들어감)와, 설정의 빠른
   대화상자(`PersonasSection.tsx` + `PersonaDialog.tsx`, 약 330줄). 후자는 스스로 전체 편집기가 다른 곳에 있다고 적고 있다.
3. **설정이 일상 작업 사이에 있다.** 흐름 종류(흐름 편집기)와 페르소나는 일을 시작하고 읽는 곳인 작업 흐름의 탭이나
   링크이고, 프로젝트와 팀은 설정에 있다. 설정이 두 목적지에 갈라져 있다.
4. **작업 흐름 탭이 여섯 개**(빠른 리뷰를 더하면 일곱)이고, 390 px 폭에서는 확인한 적이 없다.
5. **검증을 가리키는 곳이 없다.** 빠른 길은 빠른 질문뿐이고 검증된 길은 토론뿐이다. Guardian에 변경을 건네고 지적을 받는
   자리가 없다.

## 구현 메모

- **U0 (2026-11-23).** 새 프로젝트 키는 없다. D7은 `team` 키가 흐름을 가리킨다고 했고 흐름 id는 팀 id와 같은 형식이라,
  이제 `team`에 저장된 흐름이나 템플릿을 적을 수 있다. 엔진(`DebateEngine._project_flow_run`)은 요청에 팀·흐름이 없고, 스레드에
  저장된 구성이 없고, 역할별 덮어쓰기가 없을 때만 이를 `--flow`처럼(매개변수 없음, 자리 교체 없음, 사람이 쓴 과제) 해석한다.
  팀을 가리키는 키는 예전 팀 경로를 그대로 탄다. 시작할 수 없는 흐름(다른 프로젝트 종류, 자체 과제 문장)은 경고하고 팀 경로로
  돌아간다. 프로젝트 대화상자에 "기본 흐름" 선택(그 종류에서 실행 가능하고 자체 과제 문장이 없는 흐름, 목록에 없는 저장값 포함)이
  생겼다. 도중에 발견: 대화상자가 저장할 때 `team`을 버려, 대시보드에서 프로젝트를 고치면 구성이 몰래 초기화됐다. 이제 유지한다.
- **흐름 편집기 동등성 (2026-11-23), U0 중에 찾은 X1의 선행 조건.** 팀 편집기는 구성원의 워커 `host`와 `code_tools: "mcp"`를
  제공했지만 흐름 편집기는 그렇지 않았다(흐름 형식에는 둘 다 있음). 자리(정리자 제외)와 마감에 두 필드를 팀 편집기 규칙대로
  넣었다(워커가 없으면 값이 있을 때만 host 필드 표시).
- **U1 (2026-11-23).** X1, X2 삭제: `TeamsSection`, `TeamDialog`, `PersonasSection`, `PersonaDialog`, 시작 폼의 팀 선택기와
  "팀 관리" 링크, 해당 문구. 흐름을 고르지 않으면 폼이 어떤 구성으로 도는지(프로젝트 기본 흐름, 없으면 허브 기본) 알려 주고
  team을 보내지 않는다. "다시 실행"은 토론이 쓴 팀의 흐름을 고른다(팀은 변환되어 목록에 있음). 흐름을 고르면 스레드 필드가 없는
  것은 흐름의 기존 동작 그대로다. 팀의 기본 참조 코드(`context.paths`)는 더 미리 채우지 않고, 프로젝트의 참조 경로는 그대로
  적용된다. X3은 손대지 않았다(UD3 미정).
- **U2 (2026-11-23).** 설정 -> 흐름 설정은 프로젝트 | 흐름 | 캐릭터(`#/settings/flows`, `#/settings/personas[/new|/<id>]`).
  `#/settings/teams`, `#/debates/templates`, `#/debates/personas...`는 새 위치로 이어진다. 옛 링크가 계속 동작하도록 구역 id는
  `personas`로 두고 이름만 "캐릭터"/"Characters"(용어집의 말)로 했다.
- **U3 (2026-11-23)** = `verification-layer.md`의 V1c: A1(빠른 리뷰 탭, code 프로젝트의 첫 탭)과 A2(현황 "최근 검증"). 작업
  흐름 탭 순서는 제안대로(상주 에이전트가 끝). 흐름 목록의 제목은 새 위치를 따라 "흐름"/"Flows"가 됐고, 빈 토론 목록은 더 이상
  "팀을 고르고"라고 하지 않는다. U0-U3는 로컬 허브에서 1280 px와 390 px로 실제 브라우저 확인을 했다(`verification-layer.md` V1c 메모).
- **X3 (2026-11-24, UD3 승인).** 자동 부분만이 아니라 데스크톱 내보내기 폴더 전체를 없앴다. 수동 "폴더에 저장" 버튼이 쓰는
  루트를 정하는 길이 폴더 선택 화면뿐이라, 보고서 보기, 결과 탭, 산출물 탭의 폴더 버튼도 함께 빠졌다. 삭제: `AutoExport`,
  `ExportButton`, `ExportFolderSection`, `lib/exportFolder.ts`, `lib/exportThread.ts`, `lib/autoExport.ts`와 그 테스트·문구, 셸의
  `src-tauri/src/export.rs`와 명령 10개, `tauri-plugin-dialog`(그것만 dialog를 썼다. `Cargo.lock`에서 크레이트 4개가 빠졌고 버전
  변경은 없다). `inDesktopShell`은 `lib/shell.ts`로 옮겼다. 셸은 `save_download`(Markdown을 다운로드 폴더로)를 그대로 두고,
  브라우저 내려받기와 Office 내보내기는 바뀌지 않았다. tauri CI 섹션은 클라우드 컨테이너에서 돌릴 수 없었다(GTK 없음). Mac에서
  돌고, 그때 `src-tauri/gen/schemas`가 dialog 항목 없이 다시 만들어진다.

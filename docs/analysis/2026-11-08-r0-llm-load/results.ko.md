## 측정의 한계

- `other` 메모리 몫 p95가 114 %로 100 %를 넘는다. "사용 메모리"는 MemTotal에서 MemAvailable을 뺀 값인데,
  MemAvailable은 회수 가능한 페이지 캐시를 여유로 센다. 반면 프로세스 RSS에는 파일에 매핑된 페이지(Gitea와 Go
  에이전트의 실행 파일과 매핑된 파일)가 들어간다. 그래서 RSS 몫의 합이 "사용 메모리"보다 클 수 있다. 판정은 이 값에
  기대지 않는다. 메모리 압박 기준은 MemAvailable과 PSI를 쓰고, `not-needed`에는 `llm` 메모리 몫(37 %)이 필요 없다.
  R0을 다시 한다면 RSS를 MemTotal과 비교하거나 `/proc/<pid>/smaps_rollup`의 `Pss`를 읽는다.
- 평범한 사용 한 주다. 감사 실행, 넓은 multi-perspective 팀, 평가 묶음이 이 기간에 없었다. 그런 주는 다르게 보일 수
  있다.
- 허브에서 운영자가 직접 띄운 CLI 세션은 설계대로 `other`로 센다.
